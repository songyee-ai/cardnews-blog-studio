# PRD - 현재 구현 기준

## 해결할 불편과 결과
AI 입문자가 여러 소식 중 무엇을 소개할지 고르고, 날짜·조건·한계를 살린 카드뉴스를 만들도록 돕습니다. 결과는 세로형 1080×1350 PNG 7장과 출처·이미지 사용 기록이 담긴 ZIP입니다.

## 사람이 결정하는 지점
소식 후보 선택 → 전달 목적·독자 확인 → 카드별 기획 승인 → 글·그림 수정과 디자인 검수 → 현재 버전 최종 승인. 이미 정한 독자와 목적은 다시 묻지 않습니다.

## 구현 흐름
주제 입력 → Claude CLI 웹 조사 → 후보 1~3개 선택 → 필요 질문을 SQLite에 대기 상태로 저장 → 동일 엔진 세션에 답변 전달 → 편집안·스토리보드 → 별도로 생성한 이미지 가져오기 → 문구 렌더 → 부분 수정 → 최종 승인 → PNG/ZIP.
원문을 읽었다는 모델의 보고만으로 완료로 처리하지 않고 도구 응답 기록과 URL을 대조합니다. 사실, 업체 설명, 미확인을 구분합니다.

## 실행과 상태
Python HTTP 서버·SQLite가 화면과 프로젝트를 보관합니다. engine.py가 Claude subprocess를 실행하고 jobs.py가 긴 작업을 요청과 분리합니다. 브라우저는 진행 상태를 폴링합니다. 질문 ID·버전·요청 ID와 명시적 세션 ID로 답변을 연결합니다.

## 확정 디자인
Noto Sans KR 고딕 제목, 아이보리·코랄·네이비 삽화, 텍스트 쪽으로 연해지는 배경 그라데이션. 제목 72px, 핵심 문장 38px, 본문 34px. 360px 화면 환산 24/12.7/11.3px. 텍스트 위·좌우 여백 108px. 카드별 그림 이동 105/145/125/105/125/65/90px. 카드에는 출처·조사 기준 띠를 표시하지 않고 ZIP의 별도 문서에 보관합니다. 순번은 배경 대비에 따라 흰색/네이비를 선택합니다.

## 완료 조건과 한계
7장 생성, 최종 배치 확정, 앱 PNG와 검수본 파일 일치, 저장 복원, ZIP 검사까지 확인했습니다. 실제 로그인 만료·생성 API 한도 초과·실행 중 취소와 복구의 모든 실제 경로는 검증하지 않았습니다. 앱 내부 이미지 API 자동 생성 및 다른 업무로의 확장은 미구현입니다.
